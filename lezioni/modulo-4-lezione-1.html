API, integrazioni e iPhone come centro operativo

4.1 — API nella vita quotidiana: far comunicare i sistemi

Dalla richiesta pronunciata all'iPhone a un'azione controllata: capire API, autenticazione, costi e limiti senza dover diventare programmatore.

Studio indicativo 30–40 min · Testo + esercizi
Questa è una lezione testuale approfondita, non una videolezione completata. Video narrato, PDF e PowerPoint sono ancora da produrre. La durata indica lo studio, non un filmato.
Approfondimento 1

Che cos'è davvero un'API

API significa Application Programming Interface: è un insieme di regole con cui un programma chiede informazioni o operazioni a un altro. Immagina il telefono che chiede a un servizio meteo la temperatura: l'app invia una richiesta con parametri; il servizio restituisce una risposta strutturata. L'API non è necessariamente AI. Molti servizi espongono API tradizionali; un modello AI può usarle tramite un'applicazione e strumenti autorizzati.

In pratica

Esempio: per leggere un dato dal calendario serve un'interfaccia supportata dal servizio, non basta che ChatGPT conosca il nome del calendario.

Approfondimento 2

Il viaggio di una richiesta dall'iPhone

Il flusso tipico ha quattro parti: l'interfaccia sul telefono raccoglie il comando; un componente applicativo decide cosa fare; una API interroga il servizio; la risposta viene trasformata in un messaggio comprensibile. Se chiedi «mostrami le scadenze di questa settimana», un'app autorizzata interroga il calendario e poi visualizza i risultati. Se la richiesta è ambigua, il sistema deve chiedere chiarimenti prima di spostare o cancellare appuntamenti.

In pratica

Non è necessario che tutto giri sull'iPhone. Un servizio cloud può gestire l'integrazione anche con il PC spento; in alternativa, un esecutore locale deve essere acceso e raggiungibile quando serve.

Approfondimento 3

Richieste, risposte ed errori

Un'API Web spesso usa HTTPS e un metodo come GET per leggere dati o POST per inviare informazioni. I dati possono essere codificati in JSON, cioè una struttura fatta di campi e valori. Una risposta di successo non garantisce che il dato sia completo o aggiornato. Le applicazioni devono gestire errori di rete, autorizzazioni scadute, limiti di frequenza e dati mancanti.

In pratica

Esempio astratto: una richiesta di lettura può restituire il campo «temperatura» e il campo «rilevata_alle». L'orario è importante: 21 °C di ieri non equivale a 21 °C adesso.

Approfondimento 4

Chiavi API, OAuth e privacy

Molte API richiedono credenziali. Le chiavi API identificano l'applicazione o il progetto che chiama il servizio e possono comportare addebiti. OAuth consente di autorizzare un'app ad accedere a determinate risorse senza consegnarle direttamente la password. Non inserire una chiave segreta nel codice JavaScript pubblico di GitHub Pages: chiunque potrebbe recuperarla. Per chiamate riservate serve un componente protetto oppure un'architettura che non esponga segreti.

In pratica

Esempio: se CORSO I.A. è ospitato su GitHub Pages, i file del sito sono pubblici. Non vi pubblicheremo token o chiavi, neppure in file che sembrano nascosti.

Approfondimento 5

Costi: abbonamento ChatGPT e API

Un abbonamento ChatGPT e l'utilizzo delle API sono prodotti con regole di fatturazione distinte. Non bisogna presumere che una quota API sia inclusa nell'abbonamento. Per valutare un automatismo occorre stimare numero di chiamate, dimensione delle richieste e risposte, frequenza e possibili retry. I prezzi cambiano: controllali nella documentazione ufficiale prima di impegnarti.

In pratica

Esempio: dieci chiamate al mese per un rapporto familiare hanno una scala diversa da un agente che legge migliaia di documenti ogni notte. Prevedi limiti di spesa e di frequenza.

Approfondimento 6

Locale, cloud e ibrido nelle integrazioni

Un'app può inviare soltanto richieste al cloud, interrogare un modello locale sul PC oppure combinare le due modalità. Nel sistema ibrido stabilisci quali dati rimangono sulla rete domestica e quali possono essere condivisi. Se il PC di casa è spento, il modello locale non è disponibile, a meno che non esista un altro dispositivo sempre acceso. L'iPhone resta il pannello di controllo, ma non sostituisce automaticamente il computer che esegue i modelli.

In pratica

Un assistente potrebbe gestire sul cloud un promemoria senza dati riservati, mentre la ricerca fra documenti familiari potrebbe rimanere locale. Serve una separazione esplicita dei permessi.

Approfondimento 7

Dalla richiesta alla verifica

Un agente potrebbe combinare API diverse: leggere misure, creare un riepilogo e proporre un'azione. Ma lettura e scrittura devono avere privilegi differenti. Un agente che legge un calendario non deve cancellare appuntamenti senza autorizzazione. Ogni operazione importante dovrebbe produrre un log con ora, richiesta, sistema chiamato, risultato e eventuale errore.

In pratica

Progetta prima la versione in sola lettura: «mostrami le scadenze»; solo dopo valuta comandi come «sposta appuntamento», con conferma esplicita e ripristino ove possibile.

Laboratorio: progettare un assistente scadenze sull'iPhone

Questa esercitazione è progettuale: non accede a dispositivi, account o file reali.

  1. Obiettivo: vedere dal telefono le scadenze della settimana senza accendere il PC.
  2. Seleziona fonte dati: un calendario online con API e autorizzazioni appropriate.
  3. Definisci le operazioni consentite inizialmente: leggere eventi, non crearli né modificarli.
  4. Stabilisci che i segreti non saranno presenti nel repository GitHub pubblico.
  5. Disegna il percorso: iPhone → applicazione autorizzata → API calendario → riepilogo leggibile.
  6. Prevedi errori: connessione assente, autorizzazione scaduta, calendario vuoto, fuso orario diverso.
  7. Definisci il collaudo: confrontare dieci eventi campione con la fonte originale e verificare che nessun evento venga modificato.
